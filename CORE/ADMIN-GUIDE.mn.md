# Мэдээлэл шинэчлэх заавар

Админ хуудас нь сургуулийн эх, FAQ-ийн шинэ хувилбарыг тусад нь бэлтгэж, нягталсны дараа чатад ашиглуулахад зориулагдсан. Нийтэлсэн хувилбарыг сонгож буцаах боломжтой.

[Админ нээх](http://127.0.0.1:8765/admin) · [Чат](http://127.0.0.1:8765/) · [Эхийн сан](http://127.0.0.1:8765/data)

Сервер ажиллаагүй бол [ADMIN.cmd](ADMIN.cmd)-ийг нээнэ. Админ энэ компьютерт ажиллана; утасны нийтийн demo-гийн холбоосоор нээгдэхгүй.

## Код шинэчилсний дараах хувилбарын шалгалт

Эхийн хувилбарыг шалгасан кодын SHA-тай холбодог. Тэр код солигдвол хуучин
баталгааг шууд хүчинтэй гэж үзэхгүй; чат түр 503 өгч болно. Энд `seal.json`-ийг
гараар засах, active pointer-ийг устгах шаардлагагүй.

Хөгжүүлэгч локал CLI-ийн `stage-code-upgrade --label НЭР --expected-active TOKEN`
үйлдлээр одоогийн хувилбарын бүх өгөгдөл, capture, stage/seal hash-ийг шалгаад
**шинэ ноорогт** хуулна. Энэ нь хуучин seal/DB-г өөрчлөхгүй, өөрөө нийтлэхгүй.
Дараа нь шинэ release ID дээр ердийн `validate`, diff хяналт, `publish` хийнэ.
Одоогийн activation token-ийг `status`-аас авна; хуучирсан token-оор үйлдэл хийхгүй.
Энэ ажиллагаа зөвхөн локал CLI-д бий; нийтийн чат эсвэл admin HTTP үйлдлээр
кодын hash шалгалтыг тойрох зам нээгээгүй. Өөр кодод баталсан хуучин release рүү
шууд rollback хийхийг мөн хориглоно.

## FAQ шинэчлэх

1. **«Шинэ хувилбар бэлтгэх»** хэсэгт шинэчлэлээ таних нэр бичээд **«Ноорог бэлтгэх»** дарна. Жишээ нь «Холбоо барих асуултын шинэ хувилбар». Энэ үед ажиллаж буй чат өмнөх мэдээллээ ашиглана.
2. **«Сангаас унших»** дарж, засах асуултаа сонгоно. Асуулт, хариулт, өөрөөр асуух хувилбар, тайлбарыг засаж болно. Жишээлбэл, утасны тухай FAQ-д ижил утгатай асуултын нэг шинэ мөр нэмэхэд хариултын тоог өөрчлөх шаардлагагүй.
3. Доорх тулгуур эхийн холбоос, заалтыг нээж агуулга, он, тоо, хамрах хүрээг харьцуулна. **«Засварын агуулгыг тулгуур эхтэй нь нягталсан»**-ыг тэмдэглээд **«Ноорогт хадгалах»** дарна. Эхийн холбоосууд энэ засвараар хадгалагдана.
4. **«Өөрчлөлтийг шалгах»** дарна. Өмнөх ба шинэ агуулга, нэмсэн асуултын хувилбар, өөрчлөгдсөн бүртгэлүүдийг харьцуулна. **«Эх, хамрах хүрээ, хугацаа зэрэг бүх талбар»**-ыг дэлгэж бүрэн бүртгэлийг үзэж болно. Шалгалт тэнцсэн хувилбар түгжигдэнэ; цааш засах бол шинэ ноорог бэлтгэнэ.
5. Шинэчилсэн хүний нэрээ бичиж, өөрчлөлтийг эхтэй нь нягталснаа тэмдэглээд **«Чатад нийтлэх»** дарна. Чат болон эхийн сан шинэ хувилбарыг ашиглана. Чатад зассан асуултаа тавьж, хариулт, эхийн холбоосыг дахин шалгана.

Шалгалт тэнцсэн нь файл, өгөгдлийн бүтэц, эхийн холбоо, хадгалсан эхийн бүрэн бүтэн байдлыг шалгасныг илэрхийлнэ. Хариултын утга зөв, өнөөдөр хүчинтэй гэдгийг автоматаар батлахгүй. Шинэ үнэ, огноо, шаардлага нэмэхдээ бодит эх болон холбогдох баримтын бүртгэлийг хамт шинэчилнэ.

## Өмнөх хувилбарт буцаах

Зүүн жагсаалтаас өмнө нийтэлсэн хувилбарыг сонгоно. Агуулгыг нь нягталж, нэр болон шалгасан тэмдэглэгээг оруулаад **«Энэ хувилбарт буцаах»** дарна. Дараа нь чатад асуултаа дахин илгээж сэргэсэн агуулгыг шалгана. Буцаахад шинэ идэвхжүүлэлт үүсдэг; хуучин хариултын дууг шинэ хувилбарын хариулт мэт тоглуулахгүй.

Хэрэв **«Хувилбар эсвэл ноорог өөрчлөгдсөн»** гэсэн мэдэгдэл гарвал **«Төлөвийг дахин унших»** дарна. Энэ хооронд өөр хувилбар нийтлэгдсэн бол тухайн шинэ мэдээллээс шинэ ноорог бэлтгэж, засвараа дахин нягтална. Давтаж нийтлэхэд хуучин ноорог шинэ мэдээллийг дарж бичихгүй.

## Бэлэн файл, вэб эх оруулах

**«Бэлэн эх, файл оруулах»** хэсэгт төслийн `schema_version: 1`, `sources`, `facts`, `faqs` бүтэцтэй JSON багц эсвэл энэ төсөл дотор хадгалсан вэб snapshot хавтас оруулж болно. JSON импорт нь нооргийн бүтэн FAQ/баримтын багцыг сонгодог тул хэсэгчилсэн мөрийг бүтэн багц мэт оруулахгүй. Жишиг бүтэц: [одоогийн FAQ ба баримтын багц](../data/content-draft-v2-20261015.json).

Вэб эхийн импорт нь урьдчилан хадгалсан snapshot-ийг ашиглана. Энэ дэлгэц албан сайтыг хуваарийн дагуу автоматаар татдаггүй. Шинэ URL-д тулгуурласан FAQ нэмэхийн өмнө тэр албан эхийн хадгалсан хувилбар ноорогт байх шаардлагатай. Импортын дараа мөн адил өөрчлөлтийг шалгаж, эхтэй тулгаж нийтэлнэ.

Хэрэгжилт: [admin.js](../demo/admin.js), [content_release.py](../content_release.py), [release_runtime.py](../release_runtime.py). Командын хувилбар: [manage_content_release.py](../tools/manage_content_release.py).
