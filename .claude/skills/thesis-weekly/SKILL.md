# One clear weekly report

Read `CORE/SCHOOL-THESIS-GUIDE.mn.md`, the relevant W01–W32 row, current project note and actual evidence for the reporting interval. If the user provides a school template, read it before using it.

Use the actual reporting week; date alone does not prove planned work happened. Project W01 begins 2026-10-26 and is not the school's academic week 1. Allow 8–12 hours of work and one main demonstrable result, with writing alongside implementation.

Write directly readable Mongolian:

- Огноо, долоо хоногийн зорилго.
- Хийсэн ажил → бодит үр дүн → асуудал → хийсэн шийдэл/үлдсэн зүйл → шалгах нотолгоо.
- Багшаас шийдүүлэх цөөн тодорхой асуулт; эхээр аль хэдийн шийдсэн дүрмийг дахин асуухгүй.
- Дараагийн 1–3 ажил, тус бүрийн үзүүлэх зүйл.
- Actual advice, meeting date and signature remain blank until the real event/person supplies them.

For the weekly first-semester seminar, prepare a speech within the school's five-minute limit: work 1–2 minutes; result/problem/solution 1–2; next work/help about 1. Aim around 4:30 including pauses, but label it an estimate until the user rehearses aloud. Use one concrete school question to explain the work. Do not read all 32 plan rows.

State whether a result is a technical test, AI development review, raw STT score, edited transcript, decoded audio, or real human judgment. Test counts do not measure thesis completion. Do not invent participation, advice, signatures, accuracy gains or current official school dates.

Keep the original school background/table format if slides are explicitly requested. Do not create a new PPT, website or appendix for an ordinary notebook/report request. The 2026-10-30 local deck may predate the latest Gemini changes; inspect it before saying it matches current production.

Update the existing project note when new work is actually completed. Do not silently mark calendar rows complete or replace the active engineering focus with “report done.”
